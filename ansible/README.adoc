= P2Poolv2 Ansible Deployment

== Quick start

[source,bash]
----
cd ansible

# 1. Create inventory and vault from examples
cp inventory/hosts.yml.example inventory/hosts.yml
cp inventory/group_vars/all/vault.yml.example inventory/group_vars/all/vault.yml

# 2. Edit both files with your values
$EDITOR inventory/hosts.yml
$EDITOR inventory/group_vars/all/vault.yml

# 3. Encrypt the vault
ansible-vault encrypt inventory/group_vars/all/vault.yml

# 4. Dry run to verify (add -K if sudo on a host needs a password)
ansible-playbook -i inventory/hosts.yml playbook.yml --check --diff --ask-vault-pass

# 5. Deploy
ansible-playbook -i inventory/hosts.yml playbook.yml --ask-vault-pass
----

Deploy only a specific role:

[source,bash]
----
ansible-playbook -i inventory/hosts.yml playbook.yml --tags p2poolv2 --ask-vault-pass
ansible-playbook -i inventory/hosts.yml playbook.yml --tags nginx --ask-vault-pass
ansible-playbook -i inventory/hosts.yml playbook.yml --tags grafana --ask-vault-pass
----

Deploy to one host only with `--limit <host>`.

== What it does

The playbook deploys one or more P2Poolv2 instances to a host. Each instance gets its own config, systemd service, and data directory. Nginx and Grafana are configured once per host.

Three roles:

*p2poolv2*:: Installs the p2poolv2 binary and CLI, deploys the dashboard static files, templates the TOML config, and manages the systemd service. Before (re)starting a node it checks that the instance's bitcoind RPC port and ZMQ endpoint are reachable, and stops the run if not. bitcoind itself is not managed.

*nginx_p2poolv2*:: Installs nginx as a reverse proxy in front of the API with rate limiting, WebSocket support, and TLS from certificates you obtain on the host. Optionally proxies Grafana.

*grafana_p2poolv2*:: Installs Prometheus and Grafana and provisions the P2Poolv2 datasource and dashboards. See <<Grafana>>.

Each host chooses its roles with `p2poolv2_nginx_enabled` and `p2poolv2_grafana_enabled` (both default to true).

=== Binary install method

Set `p2poolv2_install_method` per host:

`release` (default):: Installs the GitHub release for `p2poolv2_version` with the official installer script, which auto-detects architecture and verifies checksums.

`source`:: Builds `p2poolv2_source_ref` (branch, tag or commit) on the host and installs the result. A dedicated `p2poolv2-build` user owns the rust toolchain (installed with rustup) and the checkout in `/var/lib/p2poolv2-build`. The build reruns only when the ref resolves to a commit other than the one installed. A first build takes 10-20 minutes and needs a few GB of RAM.

== Directory layout

[source]
----
ansible/
  playbook.yml                          # Top-level playbook
  inventory/
    hosts.yml.example                   # Inventory template (copy to hosts.yml)
    group_vars/
      all/
        main.yml                        # Shared defaults
        vault.yml.example               # Secrets template (copy to vault.yml)
  roles/
    p2poolv2/
      defaults/main.yml                 # All configurable variables with defaults
      templates/
        config.toml.j2                  # P2Poolv2 TOML config
        p2poolv2@.service.j2            # Systemd template unit
      handlers/main.yml                 # Unused; restarts are inline per instance
      tasks/
        main.yml                        # Configure and enable services
        install_release.yml             # Install from a GitHub release
        install_source.yml              # Build and install from a git ref
        preflight.yml                   # bitcoind RPC and ZMQ reachability
    nginx_p2poolv2/
      defaults/main.yml                 # Nginx-specific defaults
      tasks/main.yml                    # Install nginx, deploy site
      templates/
        p2poolv2_site.conf.j2           # Nginx site config with SSL
        p2poolv2_http.conf.j2           # HTTP-only config for certificate acquisition
      handlers/main.yml                 # Config test, then reload
    grafana_p2poolv2/
      defaults/main.yml                 # Ports, listen addresses, datasource
      tasks/main.yml                    # Install, configure, provision
      templates/
        prometheus.yml.j2               # Scrape config for the instances
        datasource.yml.j2               # Grafana datasource provisioning
        grafana-override.conf.j2        # Grafana systemd environment
      handlers/main.yml                 # Restart handlers
----

== Server layout

The roles deploy to the following paths on the target host:

[cols="1,2"]
|===
| Path | Purpose

| `/opt/p2poolv2/bin/` | p2poolv2 and p2poolv2_cli binaries
| `/opt/p2poolv2/share/static/` | Dashboard static files
| `/etc/p2poolv2/config-<instance>.toml` | Instance config (mode 0640)
| `/var/lib/p2poolv2/<instance>/` | RocksDB store and stats
| `/etc/systemd/system/p2poolv2@.service` | Systemd template unit
| `/etc/nginx/sites-available/p2poolv2.conf` | Nginx reverse proxy config
| `/etc/prometheus/prometheus.yml` | Prometheus scrape config (mode 0640, holds API credentials)
| `/etc/grafana/provisioning/` | Grafana datasource and dashboard provisioning
| `/var/lib/grafana/dashboards/` | Provisioned dashboard JSON
|===

Logs go to the systemd journal (`journalctl -u p2poolv2@<instance>`). Set `p2poolv2_log_file` to also write daily-rotated files; p2poolv2 never deletes old ones.

== Multiple instances

Define multiple entries in `p2poolv2_instances` in your inventory to run mainnet and testnet4 (or any combination) on the same host. Each instance needs unique ports. Set `enabled: false` on an instance to skip it during deployment.

[cols="1,1,1"]
|===
| Port | Mainnet | Testnet4

| Stratum | 3334 | 3333
| P2P | 6884 | 46884
| API | 46886 | 46885
| ZMQ | 28332 | 28333
|===

These are the ports in `hosts.yml.example`. The ZMQ endpoint must match the `zmqpubhashblock` setting of that network's bitcoind.

The playbook does not manage the host firewall. When you enable an instance, open its stratum and P2P ports in the firewall yourself.

== Nginx

Nginx is configured once per host (not per instance), Debian/Ubuntu only. The config includes:

- Reverse proxy to the P2Poolv2 API with rate limiting and WebSocket support
- HTTP to HTTPS redirect
- Optional redirect domains (e.g. p2poolv2.org -> testnet4.p2poolv2.org)
- Optional Grafana reverse proxy (set `p2poolv2_grafana_domain`). Set `p2poolv2_grafana_public_dashboard_path` (e.g. `/public-dashboards/<access token>`) to send visitors without a Grafana session to a public dashboard instead of the login page.
- TLS with Let's Encrypt certificates from `/etc/letsencrypt/live/<domain>/`
- Basic auth header injection toward the API backend (derived from vault credentials)

The role owns a single site, `p2poolv2.conf`, and leaves other sites on the host alone. To replace a hand-written site, list it in `p2poolv2_nginx_remove_sites`; it is removed only after `p2poolv2.conf` is in place. Every reload runs `nginx -t` first, so a broken config fails the play while nginx keeps serving the previous one.

Certificates are not managed by the playbook: obtain and renew them on the host yourself (e.g. with certbot), and reload nginx after a renewal. The role deploys the full SSL config only once a certificate exists for `p2poolv2_domain` (covering the redirect domains) and for `p2poolv2_grafana_domain` if set. Until then it deploys an HTTP-only config, which also serves certbot's HTTP-01 challenge; rerun the role after obtaining the certificates.

== Grafana

Installs Prometheus and Grafana natively (via the system package manager, not Docker). Grafana is fully provisioned from this repo; dashboards edited in the Grafana UI cannot be saved.

- Prometheus scrapes every enabled instance's API on localhost, with the API credentials when the instance has auth. Add more targets with `p2poolv2_prometheus_extra_targets`.
- Prometheus listens on 127.0.0.1 only. Grafana listens on `p2poolv2_grafana_listen_address`: `127.0.0.1` behind nginx, `0.0.0.0` for direct LAN access.
- The datasource is named `Prometheus (P2Poolv2)` with uid `prometheus-p2poolv2` and is not the default, so it never replaces a Prometheus datasource you already have.
- Both the private dashboards (`prometheus/grafana/dashboards/`) and the public ones (`prometheus/grafana/dashboards-public/`) are deployed. Grafana rescans them every 10 seconds, so dashboard changes go live without a restart. Share a public dashboard once with Grafana's *Share externally*; its link survives later deploys.
- The Grafana admin password is set from `vault_grafana_admin_password`.
- On Debian/Ubuntu the role adds Grafana's apt repository. On Arch it does not sync the package database (that would be a partial upgrade); if pacman cannot find a package, run `pacman -Syu` on the host first.
- Deploy just this role with:
+
[source,bash]
----
ansible-playbook -i inventory/hosts.yml playbook.yml --tags grafana
----
- To expose Grafana externally, set `p2poolv2_grafana_domain` and see the Nginx section above for the reverse proxy setup

This is intentionally kept separate from the Docker-based `docker/docker-compose.metrics.yml` setup, which is meant for fully-Docker deployments (where p2poolv2 itself also runs in Docker). This Ansible role targets natively-run (systemd) p2poolv2 instances instead.

== Secrets

All credentials are stored in `inventory/group_vars/all/vault.yml`, encrypted with ansible-vault. The vault file is gitignored.

To generate an API auth token:

[source,bash]
----
p2poolv2_cli gen-auth <username> <password>
----

Store the username, password, and resulting token in the vault. The nginx basic auth header and the Prometheus scrape credentials are derived from the username and password, so the token must be generated from the same pair.

With several hosts, give each host its own bitcoind RPC credentials in a per-host vault, `inventory/host_vars/<host>/vault.yml`, using the same key names (`vault_bitcoin_rpc_user`, `vault_bitcoin_rpc_pass`). Ansible loads a host's `host_vars` only for that host. Keep these keys out of `group_vars/all/vault.yml` so a missing host vault fails the run instead of silently using another host's credentials. Shared secrets (API auth, Grafana admin password) stay in `group_vars/all/vault.yml`. The `host_vars/` directory is gitignored.

== Prerequisites

* ansible-core with the `community.general` collection (tested with ansible-core 2.21)
* A target host running Ubuntu (tested on 22.04) or Arch Linux. The p2poolv2 and grafana roles support both; the nginx role supports Ubuntu only, so set `p2poolv2_nginx_enabled: false` on Arch hosts.
* SSH access with sudo privileges (run with `-K` if sudo needs a password)
* A running Bitcoin Core node on the target with `zmqpubhashblock` enabled for each network (not managed by this playbook)
* DNS records pointing your domain(s) to the target host (for Let's Encrypt, nginx role only)
